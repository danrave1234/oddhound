## Behavior

`packages/core/agent/frontier.ts` owns a persistent in-run navigation inventory. Every rendered observation contributes ordinary and hidden links, header/sidebar/menu controls, actual redirect destinations and scoped popups. The inventory survives conversation compaction and is saved as bounded `exploration.updated` deltas. It is not worker-crash resumption. An entry's independent `visited` and `checked` evidence is preserved when a later limitation changes its disposition. Safe same-origin contract exclusions remain visible as blocked/excluded inventory; they are never navigation suggestions.

All distinct named pages, bare numeric paths, pagination (`page`/`offset`) and enum filter states remain discoverable, including hash-router variants. Explicit UUID/hex/ULID record families, date/calendar variants, cursor/search and record-id queries use three representative suggestions with an explicit sampled count. An actual navigation or assertion promotes a previously sampled URL into the evidence inventory. Sampling never establishes correctness or coverage of every record.

Initial sitemap retrieval reads at most four documents per batch. `explore_next` continues unread sitemap documents with deduplication, the same 512 KiB streaming body limit and eight-second request timeout, and ordinary run lease, pacing and network controls. The finish guard counts unread sitemap documents. Unreadable and truncated documents remain report gaps. The shared URL sanitizer excludes credential-bearing query strings, including common token/session/API-key names in hash-router queries, before sitemap inventory enters events or model messages.

`finish_run` cannot dismiss discovered work merely because a small plan is complete or because earlier finish requests were refused. Three repeated finish requests without intervening action trigger actual scoped exploration. If only unattended open charters remain, the run stops with `exploration_stalled` and saved gaps. Three consecutive model responses without tools also stop truthfully; a valid tool response resets that counter. Three identical consecutive invalid tool/schema/JSON calls likewise stop with explicit gaps, rather than spending the allowance on an invalid-call loop; a valid tool resets that streak. The budget check uses the ledger's actual available allowance after the saved run cap and account ceilings. The existing action pacing, scope/actor/capability checks and 60-minute backstop remain enforced.

Browser observations wait for a bounded render window (at least 350 ms, 150 ms quiet, 1.5 s ceiling). Later observations continue collecting later discoveries. The session adopts exact-primary-origin user popups, while retaining context policy before the first request. Frameless popup navigation is classified conservatively as main-frame navigation. Runner-created independent tabs are not adopted or closed. Hover is available through ordinary observed references and label-based batches.

`check_state` and batch expectations record checked outcomes separately from visits or successful dispatches. Route checks do not assert that every control on a route works. Independent verification and original-assertion retests remain separate.

Broken-link detection distinguishes a site-advertised destination from a guessed URL. The action snapshots frontier provenance before navigation: a GET document 404 reached through an observed or sitemap-listed destination can become a replay candidate, while a guessed-URL 404 remains suppressed. The listing must belong to the current actor, device and private session generation. A link shown to the owner therefore cannot turn another actor's correct access denial into a broken-link finding. Cookie or recognized storage-token changes invalidate older listing evidence, including logout. The digest stays in controller memory; only an opaque actor/device/generation identifier is used internally. Learning the URL from the failed navigation itself cannot retrospectively establish that the site advertised it.

Session-generation invalidation is conservative: a changed non-auth cookie can also invalidate an earlier listing until a fresh observation lists it again. It is a provenance boundary, not an authentication-success test. Cookie/storage refresh occurs during observations and protected preview, so background expiry or rotation after the last refresh can still leave stale listing evidence for the next action; server-side session revocation may not change client storage at all. Any resulting candidate still needs independent replay and an explicit rule before verification. Global discovered/visited/checked evidence remains in the frontier across these changes.

## Measurements and limits

`run.timings` records monotonic elapsed time for provider attempts (retry backoff separately), dispatched exploration browser operations, observations including settling/private redaction, and the independent verification phase including evidence work. Total elapsed time additionally includes provisioning, cleanup, pacing and other controller work. These buckets are measurements, not estimates inferred from action counts. The retry regression proves two measured provider attempts and the actual retry delay. A real-site before/after comparison still needs separate evaluation evidence; local scripted exploration does not establish Meta reasoning quality or cost effectiveness.

The session learns owned-origin cookies and recognized credential/token storage fields through controller APIs and trusted CDP DOMStorage, including nested token fields. Sensitive query values from the raw observed page URL, element hrefs and hidden navigation links are also learned before sanitizing the observation, using the same matcher as sitemap filtering for ordinary and hash-router URLs. Those known values are removed from observation/history text. Model pixels remain withheld after supplied credentials or session secrets become known. The owner-preview callback gathers secrets inside the separate capture module's frozen/fenced capture sequence and enforces the primary origin. This hygiene test does not prove all transformed secrets, unknown storage conventions, canvas content or arbitrary hostile page behavior safe. The protected owner-preview security tests and remaining SELF requirements are separate gates.

Current discovery instrumentation does not guarantee full shadow-DOM/frame inventory or uncover routes that are neither observed nor listed by the target. The bounded observation window can require a later observation for slower UI rendering. Hover actions are useful for discovery; they are not yet exported as independent replay trace steps. A report must retain these limits, unreadable/truncated sitemap gaps, sampled variants, excluded effects and unexercised controls. Zero findings only describes the tested scope.
